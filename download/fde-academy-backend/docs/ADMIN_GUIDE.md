# ADMIN_GUIDE.md — running FDE Academy day to day

Audience: platform administrators and content authors. Everything below is
available through the admin API (role `admin`) or the author workflow (role
`author`). The full route index is in `API.md` Appendix A.

## 1. Signing in and roles

| Role | Can do |
|---|---|
| student | learn, quiz, download books, submit projects |
| author | create drafts, submit for review (drafts API) |
| admin | publish content, manage users, upload book editions, view analytics |

Accounts are created by self-service registration; an administrator promotes
authors/admins with a single SQL update (no password is ever visible):

```sql
UPDATE users SET role='author' WHERE email='new-author@example.com';
```

Demo accounts exist only in the sandbox deployment (see the deploy script
output); production has none.

## 2. Content workflow: create and publish a course

```
POST /api/v1/admin/cms/courses                 → draft course (code, title,
                                                 subjectId, stageId, difficulty, objectives)
POST /api/v1/admin/cms/courses/:id/modules     → module
POST /api/v1/admin/cms/modules/:id/chapters    → chapter
POST /api/v1/admin/cms/chapters/:id/lessons    → lesson (content blocks,
                                                 objectives, status)
PUT  /api/v1/admin/cms/courses/:id             → status: "published"
```

Lesson content blocks are validated server-side (`p`, `exercise`, `table`,
`steps`, `code`, `callout`, … — see `src/routes/cms.js` `validateBlocks`).
Every publish/unpublish is recorded in `publish_events` with the actor, and
every content change keeps a revision you can restore:

```
GET  /api/v1/admin/cms/revisions?entityType=lesson&entityId=<uuid>
POST /api/v1/admin/cms/lessons/:id/restore/:version
```

**Ordering rules that matter to students**: subjects have positions
(Mathematics first), stages have numbers, courses belong to a stage, and
prerequisites point at earlier stages. The roadmap a student sees is derived
from this structure — set `stageId` and prerequisites deliberately.

## 3. Book library and new editions

Books are rows with chapters; the reading experience works from the database.
Print editions are files, kept **private** and served only through signed
single-use download tokens:

```
POST /api/v1/admin/cms/uploads?kind=book&filename=new_edition.docx
     (body: raw file bytes — returns {id, checksum_sha256, visibility:"private"})
POST /api/v1/admin/cms/books/:bookId/editions
     { version: "1.1.0", format: "docx"|"pdf"|"doc"|"web", fileId: <upload id> }
```

- `format` is what the website's DOCX/PDF buttons request; a download
  without a format returns the newest edition of any format.
- Books generated by the pipeline (`fde-book-pipeline`) are published with
  `publish.py`, which refuses books that failed their QC gate.
- Students never see file paths — only the `/api/v1/books` library and
  tokenised downloads.

## 4. Watching platform health

```
GET /api/v1/admin/analytics/overview         # users, attempts, downloads
GET /api/v1/admin/analytics/content-health   # missing objectives, orphans,
                                             # unpublished lessons
GET /api/v1/admin/downloads                  # download audit log
GET /api/v1/admin/users                      # account list (no secrets)
```

`content-health` is your morning check: it flags anything a student could
stumble over (a lesson without objectives, an orphaned file, an unpublished
chapter between published ones).

## 5. Project submissions and feedback

Level 2+ projects arrive via `POST /api/v1/projects/:code/submissions`.
Evaluate with `POST /api/v1/admin/project-submissions/:id/evaluate`,
recording the verdict and feedback. Unchecked queues show in analytics.

## 6. Common tasks

| Task | How |
|---|---|
| Unpublish a lesson | `POST /api/v1/admin/cms/lessons/:id/unpublish` |
| Fix a wrong quiz option | edit the seed/source content, re-seed, or patch via CMS revisions |
| Add a glossary term | seed `glossary` array (needs `simple`, `detailed`, `example`, `related`, `category`) |
| Rotate the JWT secret | change `FDE_JWT_SECRET` in `.env` and restart (users re-login) |
| Take the site down | `systemctl stop fde-academy` (or kill the node process) |
| Verify everything still works | run the two E2E scripts (10 + 8 steps) |

## 7. Safety rules the platform enforces for you

- Lesson completion requires a **passing graded attempt** — you cannot mark
  progress for a student through the API.
- Edition files must be `private`; the CMS rejects public files.
- Every upload is checksummed; downloads verify the token, expiry and
  single-use bit server-side.
- Registration cannot escalate roles (unknown fields are stripped).
- Demo users and reset-token exposure are hard-off in production mode.
