# DEPLOYMENT.md — FDE Academy production deployment

This guide deploys the complete platform: one Node.js process serves the
website (SPA) **and** the API, backed by PostgreSQL and private file storage.

```
browser ──HTTP──> node src/server.js ──> PostgreSQL (books, users, progress)
                     │                    └─ storage/ (private DOCX/PDF files,
                     │                       served only via signed tokens)
                     └── GET /  public/index.html  (the bundled SPA)
```

## 1. Requirements

| Component | Version | Notes |
|---|---|---|
| Node.js | >= 20 (24 LTS recommended) | `node --version` |
| PostgreSQL | 16+ | OR the embedded PGlite build (zero external services) |
| OS | any Linux | systemd unit below |
| Disk | ~2 GB | database + book files + backups |

Two database modes:

- **Embedded mode** (`FDE_PGLITE_DIR=pgdata`): real PostgreSQL compiled to
  WASM, storing to a directory. Zero external services, perfect for a single
  host. **This is the mode of the reference deployment.**
- **Server mode** (`DATABASE_URL=postgres://…`): a normal PostgreSQL server,
  required when `NODE_ENV=production` (the fail-fast config check enforces
  `DATABASE_URL` so an embedded database is never silently used in
  production).

## 2. Install

```bash
unzip fde-academy-backend.zip && cd fde-academy-backend
npm install --omit=dev        # installs only the embedded database engine
bash ops/deploy.sh            # generates .env, migrates, seeds, starts
```

`ops/deploy.sh` writes `.env` once with a freshly generated
`FDE_JWT_SECRET` (`openssl rand -hex 48`). **`.env` is gitignored — never
commit it.** All secrets come from the environment; the repository contains
none.

The deploy script prints the sandbox demo sign-in if demo users were enabled.
For **real production**, start with `FDE_SEED_DEMO_USERS` unset and create
the first admin instead:

```bash
# after registering your own account:
psql "$DATABASE_URL" -c "UPDATE users SET role='admin' WHERE email='you@example.com';"
# embedded mode: node -e 'import("./src/db/index.js").then(...)' or run
#   node src/db/migrate.js  — then use any SQL client against pgdata/
```

## 3. Environment variables

| Variable | Default | Purpose |
|---|---|---|
| `NODE_ENV` | development | `production` enables fail-fast checks |
| `FDE_JWT_SECRET` | (generated) | signing key — **required in production**, >= 32 bytes |
| `FDE_PORT` / `FDE_HOST` | 8787 / 127.0.0.1 | listen address |
| `DATABASE_URL` | — | external PostgreSQL (required if `NODE_ENV=production`) |
| `FDE_PGLITE_DIR` | (in-memory) | embedded PostgreSQL data directory |
| `FDE_STORAGE_DIR` | `storage/` | private file storage (book files) |
| `FDE_LOG_LEVEL` | info | debug / info / warn / error |
| `FDE_CORS_ORIGIN` | (same-origin) | set only if the SPA is hosted elsewhere |
| `FDE_STATIC_FILE` | `public/index.html` | the bundled SPA; empty disables serving |
| `FDE_ACCESS_TOKEN_TTL_MIN` | 15 | access-token lifetime |
| `FDE_REFRESH_TOKEN_TTL_DAYS` | 30 | refresh-token lifetime (rotating) |
| `FDE_DOWNLOAD_TOKEN_TTL_MIN` | 10 | book-download link lifetime (single use) |
| `FDE_SEED_DEMO_USERS` | off | sandbox demo accounts; **must stay off in production** |
| `FDE_AI_TUTOR` / `FDE_AI_PROVIDER` | auto | AI tutor on/off and provider |

Full list with explanations: `.env.example`-style table above and
`src/config.js` (single source of truth). Password policy, reset tokens and
hashing parameters live in `src/auth/passwords.js` (argon2id-class scrypt
hashing; no plaintext ever stored).

## 4. Database migrations

```bash
node src/db/migrate.js up        # applies every pending migration, in order
node src/db/migrate.js status    # shows applied/pending
```

Migrations are plain SQL files under `src/db/migrations/`, tracked in the
`schema_migrations` table. Run `up` on every release; migrations are
forward-only by design (see rollback below).

## 5. Publishing the book library

The seeder creates a working library with placeholder editions so a fresh
install is never broken. To serve the **full print editions** (DOCX + PDF
generated by the book pipeline):

```bash
cd fde-book-pipeline && python3 build.py --book all   # 6 books through QC gates
python3 publish.py --base http://127.0.0.1:8787       # uploads + attaches editions
```

`publish.py` refuses any book whose QC gate failed. Run it after every
content release. Reference sizes: 450–660 KB per edition.

## 6. Logging and error monitoring

- Structured JSON logs to stdout: `ts, level, msg, component` plus request
  ids on every API response (`X-Request-Id`). Ship stdout to your collector.
- Uniform error envelope `{"error":{"code","message"}}` — no stack traces
  leak to clients; `clientError` sockets are destroyed.
- **Recommended monitoring stack** (not bundled): journald or Docker logs →
  Loki/ELK; alert on `level>=warn` rate, 5xx rate, p95 latency, and the
  `/api/v1/health` probe (add an uptime check — it returns
  `{"ok":true,...}`).
- `/api/v1/admin/analytics/content-health` gives an internal content QA
  report (missing objectives, unpublished lessons, orphan files).

## 7. Backup strategy

```bash
bash ops/backup.sh                       # → backups/fde-<timestamp>.tar.gz
bash ops/backup.sh --restore backups/fde-<stamp>.tar.gz
```

Backs up `pgdata/` + `storage/` + `.env` (the JWT secret — protect backups
with the same care). Schedule: daily, keep 7 daily + 4 weekly off-site.
In server mode, use `pg_dump` for the database and snapshot `storage/`.
Verify restores quarterly on a staging host (the E2E scripts below make
this a 5-minute check).

## 8. Rollback plan

1. **Bad release, data fine** — redeploy the previous source zip, run
   `node src/db/migrate.js status` (migrations are additive; if a new
   migration must be reverted, restore from backup — hence daily backups).
2. **Bad data** — stop the service, `ops/backup.sh --restore <file>`,
   restart with `bash ops/deploy.sh --restart`.
3. **Bad book edition** — no rollback needed: publish a newer edition
   (editions are additive and the library always offers the newest of each
   format); use the CMS to unpublish if required.
4. Keep the last two release zips so option 1 is a two-minute operation.

## 9. systemd unit (single host)

```ini
[Unit]
Description=FDE Academy
After=network.target

[Service]
Type=simple
User=fde
WorkingDirectory=/opt/fde-academy-backend
EnvironmentFile=/opt/fde-academy-backend/.env
ExecStart=/usr/bin/node src/server.js
Restart=on-failure
RestartSec=3
# hardening
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ReadWritePaths=/opt/fde-academy-backend/pgdata /opt/fde-academy-backend/storage /opt/fde-academy-backend/backups

[Install]
WantedBy=multi-user.target
```

Put a reverse proxy (Caddy/Nginx) in front for TLS and request-size limits;
the app itself binds `127.0.0.1` by default. Rate limiting is deliberately
**not** in the app (zero runtime dependencies) — enforce it at the proxy
(see SECURITY.md).

## 9b. Hosted platform quickstart (Render / Railway / Fly.io / any Node host)

The app is a single Node.js process with **no build step** (the SPA ships
committed at `public/index.html`), so any host that runs Node 20+ works.
Create one **Web Service** (Node) + one **PostgreSQL** instance (13+) with a
persistent disk for `storage/`. No credentials belong in the repository —
set everything as host environment variables:

| Variable | Value on the host |
|---|---|
| `NODE_ENV` | `production` |
| `DATABASE_URL` | the managed PostgreSQL connection string |
| `FDE_JWT_SECRET` | `openssl rand -hex 48` (generate once, keep stable) |
| `FDE_HOST` / `FDE_PORT` | `0.0.0.0` / the port the host routes (leave unset if the host injects `PORT`) |
| `FDE_STORAGE_DIR` | absolute path on the **persistent disk** (e.g. `/var/data/fde-storage`) |
| `FDE_SEED_DEMO_USERS` | **unset** (the config refuses to boot if it is set to 1) |

```bash
# Build command (nothing to compile — install the optional pg driver):
npm ci --omit=dev
# Release command (first deploy):
node src/db/migrate.js up && node src/db/seed.js
# Start command:
node src/server.js
```

Create the first admin after registering your own account:

```bash
psql "$DATABASE_URL" -c "UPDATE users SET role='admin' WHERE email='you@example.com';"
```

Publish the print editions from a machine with the repo (see section 5):
`FDE_DEMO_PASSWORD` is not needed — publish.py accepts `--email/--password`
for any admin account.

Split deployment alternative: serve `public/index.html` from a CDN/static
host and run the backend API-only by setting `FDE_STATIC_FILE=` (empty) and
`FDE_CORS_ORIGIN=https://your-frontend-host`. Signed book downloads keep
working because they are API routes, not static files.

## 10. Post-deploy verification (5 minutes)

```bash
curl -s http://127.0.0.1:8787/api/v1/health          # {"ok":true}
curl -s http://127.0.0.1:8787/ | head -c 200         # <!DOCTYPE html> …
python3 scripts/e2e_student.py                       # 10/10 steps
python3 scripts/e2e_admin.py                         # 8/8 steps
```

The two E2E scripts exercise the complete student and admin journeys,
including DOCX and PDF downloads and progress tracking. If they pass, the
platform is whole.
